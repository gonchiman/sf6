# 標本調査ページの実装案

2026年10月27日

以下は初期の縦積みパネル案の記録。2026年10月27日の追加指示により、画面を結果閲覧専用に変更し、取得設定・実行管理はGitHub Actionsへ移した。現在の仕様・公開条件は [実装状況](README.md) を参照。以下の画面内取得操作、プロフィール・継続観測の記述は現在の対応範囲を示すものではない。

ランク別の標本を抽出し、同じアカウントを再観測できる専用ページ `#sample-survey` を追加する。マスター全体の調査と、今ActのMR帯別調査は別の標本系列として扱う。最初は一覧で確認済みの項目を取得し、プロフィールの公開項目を確認した後に分析対象を広げる。

## 初期の調査条件

| 系列 | 抽出元 | 初期の抽出枠 |
| --- | --- | --- |
| ランク別 | 固定条件の最大LP一覧。ROOKIE〜MASTERの8ランク | 各200枠、計1,600枠 |
| MR帯別 | 今Act・最大MR一覧 | 各100枠、計600枠 |

MR帯は1200未満、1200以上1400未満、1400以上1600未満、1600以上1800未満、1800以上2000未満、2000以上の6区分とする。初期値は変更可能にし、MR追加調査は独立して有効・無効を選べる。ランク別のMASTERはMR追加調査を有効にしても残す。

2,200枠は二つの系列の合計であり、重複のない2,200アカウントを保証する数ではない。重複IDを把握し、同じ観測値を共有できる場合も、所属する標本系列・抽出条件は別々に保存する。

## 画面構成

「調査条件」「取得状況」「調査結果」を縦に配置する案を採用する。

### 調査条件

- 対象ランク、ランクごとの標本数、MR追加調査、MR帯ごとの標本数を設定する。
- 調査方法は初回抽出を初期状態とし、名簿ができた後に「同じ標本を再取得」「新しく抽出」を選べるようにする。
- 抽出枠の合計、系列別の内訳、取得時間の参考値、1回の時間上限との比較を表示する。
- 計画の保存時に設定版を固定する。編集中の設定と実行中・過去の観測条件を混同しない。
- 取得可能な項目と未確認の項目を短い状態表示で区別する。未確認項目は取得対象として選択できない。

### 取得状況

- 初期はローカル実行。計画保存、開始、停止、保存済み計画の再開を扱う。
- 準備中、取得中、部分取得、完了、停止、失敗を区別する。処理中は実行条件の編集を固定する。
- 抽出枠の処理数、取得できたアカウント数、ページ読取数、経過時間、取得開始・終了日時、停止理由を表示する。それぞれの単位を混ぜない。
- 中断後は保存した名簿と進捗を使う。認証要求・アクセス制限で停止した実行を自動再試行しない。

### 調査結果

- 観測回を選び、「ランク別」「MR帯別」を切り替える。初期は表を中心とし、グラフを必須にしない。
- 予定枠、観測アカウント数、項目ごとの有効数・欠測数、選択した統計量を示す。
- 一覧項目だけの段階ではLP・MRなどの標本内の値を表示する。最終活動、キャラ別成績、操作タイプの分析は、読み取りと定義を確認してから追加する。
- 未取得、非公開、項目なし、読み取り失敗、実際の0を別の状態にする。MR不明を非活動、0MR、1500MRへ置き換えない。
- 出典、固定条件、観測期間、対象Act、標本系列を簡潔な値として表示する。説明文・自動追加のヘルプは置かない。
- 全体の推定はLP系列のランク人口による重み付けで行い、MR追加標本をそのまま加えない。母数・抽出条件・欠測の扱いが揃わない場合は推定前とする。

## 取得項目

| 項目 | 現在の根拠 | 実装での扱い |
| --- | --- | --- |
| CFN ID、LP、ランク・ティア、表示位置、取得日時 | LP一覧の既存readerと観測処理 | 初期対象。IDの永続保存は専用処理を作る |
| MR、表示位置、対象Act | MR一覧の既存reader | MR系列で初期対象 |
| 最終プレイ・ログイン、モード別対戦数 | プロフィールreaderで未確認 | 少数確認後、意味を区別して追加 |
| キャラ別対戦数・勝数・LP・MR | プロフィールreaderで未確認 | 公開範囲と集計期間を確認して追加 |
| 操作タイプ別の利用 | プロフィールreaderで未確認 | 現在設定と対戦実績を区別して追加 |

一覧で分かるIDを基準に同じアカウントを追跡する。最大LPと最大MRのキャラクターが一致するとは仮定しない。初めて標本に入ったIDを新規参入者として数えない。

## 抽出と継続観測

1. 実行時の条件・掲載総数と、各ランクまたはMR帯の境界を確認する。古い保存分布は計画の参考値にとどめ、抽出区間を無条件に流用しない。
2. 各区間の表示位置から重複なしで無作為抽出する。乱数seed、抽出手順の版、位置、区間、母数、確認時刻を保存する。同順位があるため表示順位の数値だけを位置として使わない。
3. 同じページにある選択位置はまとめて読み取る。一覧の20行をすべて取得する方式を、個人の無作為抽出と同じものとして扱わない。
4. 予定位置のアカウントIDと観測値を保存する。取得順は一つのランクだけに偏らないよう事前に混ぜる。失敗した位置を取りやすい別IDで黙って置き換えない。
5. 次回は保存したIDを再観測する。抽出時の層と現在のランク・MRを別々に持ち、昇格・降格で対象者を入れ替えない。

ランキングは取得中にも変わる。境界の変化、予定位置と実際の層の不一致、ID重複を記録し、固定名簿からの厳密な無作為抽出を実現したと断定しない。信頼区間は抽出設計と欠測の扱いを検証してから表示する。

固定標本は、その後に参入したアカウントを代表しない。新しい標本を抽出した場合は別の系列版にし、継続観測と入れ替え標本の結果を識別する。

## 時間の見積もりと実行上限

計画段階の参考値は、選択された一覧ページ数に1ページ5〜10秒を掛ける。ページ数がまだ決まっていない画面案では、1枠1ページと仮定する。初期2,200枠なら一覧のみで約3.1〜6.1時間となり、2時間の運用目標を超える。

この参考値には境界の確認、起動、再読、プロフィールの追加画面を含めない。プロフィールを有効化する際は必要画面数と実測時間を別に加える。実行開始後は実測値で残り時間を更新し、推定できない場合は未算出とする。

初期の取得は直列・全体の開始間隔10秒を仮設定とし、これを安定取得の保証とは扱わない。時間上限は初期2時間、読取回数にも明示的な上限を設定する。上限に達したら部分取得として進捗を保存する。回数には準備・境界確認・再読も含める。

既存の並列テスト専用runnerは連続20または50ページ、200読み取り・10分の検証用であり、その上限を変更して転用しない。標本調査用runnerを新設し、認証判定・条件検証・開始間隔の待機・停止処理の必要部分を共通化する。

## 保存と実行環境

ローカルでは `.local/sample-survey/` に計画・対象者台帳・観測履歴を保存する。CFN IDと内部の永続IDを対応付け、個別の値と欠測理由を観測回ごとに保持する。DBの更新はトランザクションで行い、同じ観測回の再保存・再開で重複集計しない。

既存LP・MR readerの匿名キーはreaderごとにsaltが変わるため、継続追跡のIDには使えない。`player-observation-store`の非公開パス検証や冪等保存は参考にし、初観測台帳へ調査の観測値を混在させない。

ブラウザー側へ認証Cookieを渡さず、既存と同様に取得サービス側で扱う。配信用JSONは検証済みの集計値だけとし、対象IDと個別時系列は含めない。GitHub Pagesでは集計の閲覧・読み込みを扱う。

GitHub Actionsで継続観測するには、対象者台帳と個別時系列を次の実行へ渡せる非公開の永続保存先を先に決める。公開リポジトリのコード・artifactに台帳をそのまま保存しない。保存先が決まった後、専用workflowと既存の要求ID照合・実行状況確認・停止の仕組みを接続する。週次スケジュールは実行の成立を確認してから別途設定する。

## 実装順序と確認項目

1. **画面と計画**：`SampleSurveyPage`、条件・履歴・結果の部品、型、入力検証、ルートを追加。合成データで状態と画面を検証する。
2. **抽出と一覧取得**：区間内の抽出、同一ページのまとめ読み、非公開台帳、直列runner、途中保存を作る。小規模の読み取りで実装を確認する。
3. **プロフィールと継続観測**：公開項目を確認したreaderだけを追加し、IDからの再取得と項目ごとの欠測を検証する。
4. **クラウドと定期更新**：非公開保存、専用workflow、要求ID照合、結果読み込みを接続した後に週次更新を設定する。

抽出の再現性・重複・範囲外、母数より多い標本の指定、掲載位置の移動、停止後の再開、項目欠測と0、二つの系列の重複、重み付き集計を重点確認する。UIは未取得・部分取得・完了・認証停止、実行中の条件固定、キーボード操作、320px以上の表示を確認する。

実サイトが人間確認やアクセス制限を返した場合は停止し、取得成功や再開可能と見せない。画面案の操作は設計プレビュー内の状態変更のみで、実データの取得を行わない。
