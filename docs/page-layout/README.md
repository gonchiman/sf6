# 新規ページの標準構造

## 用途と適用範囲

新しいページの提案・設計・実装と、既存ページを標準構造に移すときに使う。結果の画像保存ボタンを追加する場合や、その見た目・配置を見直す場合は「画像保存ボタン」も適用する。

`arknights_2` のページ標準から、設定・結果の配置、共通見出し、結果ごとの操作をSF6向けに採用する。既存ページへの適用は依頼された範囲で行い、列幅や軸などの通常の修正に合わせてページ全体を移行しない。

## 保存場所と再利用する部品

| 参照先 | 役割と現在の状態 |
| --- | --- |
| [ルート定義](../../src/lib/routes.ts)、[ナビゲーション](../../src/lib/navigation.ts)、[App.tsx](../../src/App.tsx) | 実装済みのページ登録先。現在はナビゲーションの表示名とApp側のタイトル指定が別にある。 |
| [AppShell](../../src/components/AppShell.tsx)、[navigation.css](../../src/navigation.css) | 実装済みの共通メニュー・ページ見出し・画面幅への対応。本文側で同じページ見出しを追加しない。 |
| [ContentTabs](../../src/components/ContentTabs.tsx) | 実装済みの結果タブ。選択状態、タブとパネルの関連付け、矢印キー・Home・Endの操作を再利用する。 |
| [StatisticsPanel](../../src/components/StatisticsPanel.tsx) | 実装済みのセクション見出しと`headerContent`。個別の設定セクションや既存パネルに操作を置く場合の候補。 |
| [Steam同時接続数ページ](../../src/components/SteamPlayerCountPage.tsx)、[ゲーム比較表示](../../src/components/SteamPlayerCountComparisonView.tsx) | 設定・結果タブ・表示尺度の分離を確認できる実装例。この標準全体を適用済みという意味ではない。 |
| [ページ内のアドレスとコピー操作](../element-location-copy/README.md) | コピー対象・文字列・操作の仕様。新設する設定セクション・出力・表示形式の設計時に併用する。 |

本文幅と出力操作行をまとめる共通部品、アドレスコピー、画像保存の共通ボタンは未実装。導入時は上記の既存部品を確認し、必要な共通部分をこのリポジトリの`src/components/`と対応するCSSへ置く。兄弟プロジェクトの部品やAPIが既に使えるとは扱わない。

## 固定仕様と可変部分

- 本文は、全体に効く設定、結果の切り替え、選択中の結果の順に並べる。設定がなければ結果から始め、結果が1つならそのまま表示する。結果固有の操作はその結果の近くに置く。
- 標準構造の本文は上限960pxを基本として中央に配置し、設定・タブ・結果の左右端をそろえる。狭い画面ではアプリのページ余白内に収め、設定行を折り返す。横幅が必要な表などは、その出力領域でスクロールさせる。既存の共通シェルの幅や全ページのCSSを一括変更しない。
- ページの`h1`は`AppShell`が提供する。本文に同じページタイトルを繰り返さず、区別が必要な設定・結果だけに見出しを付ける。表・グラフ自身の枠に装飾目的のパネルを重ねない。
- 結果が複数なら、下線で選択状態を示すタブを使う。同じ結果を表・グラフなどに切り替える操作は結果の上に置き、選択状態を読み上げでも伝える。表示が1種類なら切り替え操作を作らない。
- 見出し・タブ・表示切り替えは左、結果に対する画像保存・アドレスコピーは右に置く。狭い画面でも操作を隠さず、折り返して押せる範囲を確保する。
- ページ名・タブ名・表示形式名は表示とコピーで同じ定義を使う。新設・移行する範囲で表示名の定義をまとめ、画面にない内部名をコピーに使わない。

ページ名、設定項目、タブの数と名称、表示形式、データ、初期選択はページごとの入力とする。出典・対象期間・取得状態・単位など、結果の判断に必要な表示は[UIの補足テキスト方針](../../instructions/ui-text.md)に従って保持する。

## 画像保存ボタン

この節は画面上の操作の配置と見た目を扱う。グラフの画像出力を作成・変更するときは[グラフ画像出力](../chart-image/README.md)、表の場合は[テーブル画像出力](../table-image/README.md)の仕様も読む。

- 単一結果では見出し・表示切り替えの行、複数結果ではタブ行の右端に、左から「画像を保存」「アドレスコピー」の順に並べる。保存対象は表示中の結果と結び付け、保存できる表示でだけ保存ボタンを出す。
- 通常時の保存ボタンは、受け皿に向かう下矢印のアイコンで示す。コピーと大きさ・色・ホバー・フォーカス表示を共通化する。通常の外観は28px四方を基準とし、狭い画面やタッチ操作では押下領域を44px四方以上に広げる。実装時に値を共通CSSへ集約し、以後はその定義を参照する。
- ネイティブの`button`を使い、読み上げ名を「画像を保存」とする。ダイアログを開く場合は`aria-haspopup="dialog"`を付け、閉じた後に起動元へフォーカスを戻す。処理中・失敗・利用不可も読み上げで判別できるようにする。
- ボタンのための説明文やツールチップを自動で追加しない。操作列とコピー文字列は保存画像に含めない。画像の内容・プレビュー・保存先の扱いは各出力仕様に従う。

## 使い方

1. [ルート定義](../../src/lib/routes.ts)と[App.tsx](../../src/App.tsx)へ新しいページを接続する。メニューに載せる場合は[ナビゲーション](../../src/lib/navigation.ts)にも登録する。ページ表示名とコピー用のページ名の定義元をそろえる。
2. 全体設定・結果・結果固有の操作を分け、どのまとまりをチャットで個別に指すかを決める。アドレスコピー仕様に沿って、設定を含む各対象のコピー位置と文字列を案に示す。
3. `AppShell`と`ContentTabs`を再利用する。出力操作行や本文枠の共通部品が必要なら、対象ページの実装と同じ作業で追加する。共通部品の導入を理由に無関係な既存ページを移行しない。
4. タブ名は`ContentTabs`の`options`、表示形式名は切り替えの定義をコピー処理でも参照する。タブパネルには対応する`id`と`aria-labelledby`を付ける。

たとえば既存の[Steam同時接続数](../../src/components/SteamPlayerCountPage.tsx)を標準構造へ移す依頼では、次の配置にできる。これは導入時の設計例で、現在の画面にコピー操作があるという意味ではない。

| まとまり | 配置例 |
| --- | --- |
| 表示条件 | 上段の設定セクション。見出し行の右端にその場所のコピーを置く。 |
| 時間帯比較・期間比較・時間帯一覧・取得履歴 | 選択したゲーム数に対応する既存タブ定義を使い、右端に選択中の結果の操作を置く。単一ゲーム用の「観測推移」も既存の条件分岐を維持する。 |
| 人数・各ゲーム平均＝100 | 時間帯比較の表示尺度として結果の近くに置く。選択中の表示名をコピー内容にも使う。 |

## 見本・適用状況と更新

この標準は仕様として保存している。共通ページ枠・出力操作行・コピー・画像保存を組み合わせたSF6の適用済みページや画面見本はまだない。上記の既存実装は構成と部品の参照元であり、標準全体の完成見本ではない。

最初の導入時に、実在する共通部品へのリンクと最小の利用例を登録する。見本を追加する場合は実装した画面から作成し、`examples/`に対象ルート・選択状態・画面サイズ・表示倍率・更新手順とともに保存する。見本の数値やタブ数は固定仕様にしない。

## 変更時の確認

- PCで設定・タブ・出力の左右端、狭い画面でページ全体の横はみ出しと操作の押しやすさを確認する。
- ページの`h1`が共通シェルから提供され、本文に重複しないこと、出力の二重枠や不要な説明帯が増えていないことを確認する。
- タブを矢印キー・Home・Endで移動でき、選択状態・パネルの関連付け・フォーカスが正しいことを確認する。
- タブ・表示形式を変えた際に、保存対象とコピー内容が現在の表示へ追随することを確認する。コピー操作の検証はアドレスコピー仕様に従う。
- 実装変更では画面と対象の実出力を確認する。仕様だけを変更した場合はリンク・適用範囲・現在の実装との区別を確認し、未作成の部品を実在するリンクとして登録しない。
