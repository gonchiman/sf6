# 比較系列の配色方針

キャラクターや操作タイプなどを色で区別する表示を新規作成・修正するときに適用する。画面上のグラフ・凡例・保存プレビュー・保存画像で共通の意味を維持する。

## 定義と使い方

- 対象のIDと色の対応を、共通の定義元で管理する。同じ対象は同じ色を使い、並び順、表示名、フィルターの結果だけで色を変えない。
- キャラクター、操作タイプ、ランクなど、何を色で区別するかをグラフごとに明確にする。異なる分類の色を、説明なく同じ意味として扱わない。
- 色に加えてラベル・線種・記号なども使い、色だけで対象を識別させない。
- データ欠損や未知の対象は、実在する対象と区別する。欠損を特定キャラクターや操作タイプの色として表示しない。
- 既存の配色を変更する場合は、画面、凡例、プレビュー、保存画像への影響を確認する。

## 共通定義と見本

- アークナイツのMODや潜在に対応する色・分類・濃淡のルールは流用しない。SF6の対象と分類に合わせて定義する。
- [キャラクター系列の共通定義](../../src/lib/seriesColors.ts) が、勝率データの `characterId` と色・線種・記号の対応を管理する。操作タイプやランクの配色は、この定義の対象外とする。
- [配色見本SVG](examples/characters.svg) は、[生成スクリプト](../../scripts/render-series-colors.ts) が共通定義と公開キャラクター一覧から作る実装確認用の見本。SVGを直接編集したり、別のパレットを手作業で管理したりしない。

## キャラクター系列の固定仕様

- `characterSeriesStyle(characterId)` は `color`、`dashArray`、`marker` を返す。実線は `dashArray: undefined`、記号は `circle`・`square`・`triangle`・`diamond` のいずれか。戻り値は読み取り専用とする。
- 色・線種・記号はIDごとに明示して固定する。表示順、選択順、絞り込み、表示名、月、リーグ、操作タイプによって割り当てを変えない。新しいキャラクターを追加しても既存の割り当てを並べ直さない。
- キャラクター一覧の `ehonda`・`gouki_akuma`・`vega_mbison` は、それぞれ勝率データの `honda`・`gouki`・`vega` と同じ定義を使う。表示名からの推測や大文字・小文字の自動変換は行わない。
- 未登録IDは専用のグレー・線種・記号へ戻す。既知キャラクターの色を順番やハッシュで借りない。複数の未登録IDを表示する場合も、必ず名前を併記して識別する。
- 背景は白を基準とし、線・記号の色は白とのコントラスト比3:1以上を維持する。色だけで見分けられることは前提にせず、名前・線種・記号を併用する。
- 欠損値は未知IDとは別に扱う。欠損をゼロの点として描かず、欠損の前後を線でつながない。配色関数は値や欠損状態を判定しない。

名前、表示順、線の座標、線幅、記号サイズは利用側が決める。色・線種・記号の種類は共通定義をそのまま使い、凡例とグラフで一致させる。

```ts
const style = characterSeriesStyle(fighter.characterId)
// SVGのstrokeにstyle.color、strokeDasharrayにstyle.dashArrayを使う。
// 点はstyle.markerに対応する形で描き、キャラクター名を併記する。
```

## 棒グラフの控えめな配色

- [棒グラフ用の派生定義](../../src/lib/characterBarColors.ts) の `characterBarSeriesStyle(characterId, useCharacterColors)` は、共通のキャラ色をグレーに寄せた色と、元の線種・記号を返す。棒の大きな塗り面に使い、元の系列定義は変更しない。
- 第2引数の初期値は `true`。`false` では既知キャラの色を同じグレーにする。別名IDは元の対応を引き継ぎ、未登録IDは専用のグレー・線種・記号を維持する。
- 期待試合数ページの棒・凡例に適用する。グラフは表示専用で、棒からキャラを選択しない。「キャラ色を使う」の切り替えは表示用で、計算値や棒の高さ、比較するキャラを変えない。
- 凡例は `CharacterSeriesKey` の `seriesStyle` に同じ派生定義を渡す。省略すると既存の配色を使う。線グラフや既存の配色見本SVGは元の系列定義を使う。
- 変更時は `src/lib/expectedMatchesChart.test.ts` で全既知色の白背景とのコントラスト3:1以上、ID・別名の対応、無色時の統一、元の定義が変わらないことを確認し、画面でも棒と凡例の一致を確認する。

## 見本の再生成と確認

プロジェクトルートで実行する。Node.jsの対応バージョンは [package.json](../../package.json) に従う。

```sh
node scripts/render-series-colors.ts
node scripts/render-series-colors.ts --check
```

生成時には公開キャラクター一覧と全勝率データを読み、IDの網羅性、別名対応、定義の重複、未知IDの分離、白背景とのコントラスト、参照順による不変性を確認する。`--check` は生成内容と保存済みSVGが一致することも確認し、ファイルを書き換えない。

更新時は見本を開き、長い名前やIDが重ならないこと、線種と記号を識別できることを確認する。実際のグラフでも複数キャラクターを選び、凡例との一致、並べ替えや絞り込み後の同一性を確認する。
