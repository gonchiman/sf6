# MR分布の仕様と取得手順

ランク分布ページの「MR帯」では、Bucklerの今Act・最大MR一覧を100MRごとに分け、掲載件数と割合を表示する。取得中に更新される一覧の境界位置から求める概数で、LPランク分布とは別の対象として保存・表示する。

## 表示と集計対象

`#rank-distribution`の「分布の対象」で「LPランク」と「MR帯」を切り替える。MR帯も条件選択、縦棒グラフ、数値の表の順に配置し、取得日と棒の値を選べる。初期値は最新の取得日と「MR一覧比（%）」、件数表示は「アカウント数（件）」。

グラフの表示範囲は「主要範囲」を初期値とし、1000以上2200未満の12区分を表示する。「全範囲」で0〜99から2500以上までの26区分へ切り替える。表示範囲外の件数・割合は、選択した取得日の実データから求めて併記する。範囲を狭めても割合の分母はMR一覧の全掲載件数を維持し、表示中の区間だけで100%に換算しない。数値の表は範囲選択にかかわらず全26区分を保持する。

階級の表記は次の4種類から選べる。ここでの階級は100MRごとの区間を指す。

| 表記 | 区間名の表示 |
| --- | --- |
| 区間（2行） | 初期値。各区間の下限と上限を2行に分けて表示する |
| 区間（1行） | `1500〜1599`のように各区間を1行で表示する |
| 下限 | 各棒の下に区間の下限を表示する |
| 数値目盛 | MRの数値を横書きの目盛として表示し、幅に応じて目盛を間引く |

区間・下限の3種類は、各棒に対応する階級名をすべて表示する。幅が足りる場合は横幅内に収め、足りない場合だけ棒と階級名を一緒に横へスクロールする。スクロールしても縦軸は固定し、初期位置では分布の山が見えるようにする。「数値目盛」はすべての棒を保ったまま、目盛の文字だけを間引く。

棒は隣り合う区間の隙間を抑えて太く表示する。0件・0%の数値ラベルは省き、正の値は最大値を優先して重なりを避ける。グラフ上の正の割合が0.01%未満の場合は「0.01%未満」と表示し、実際の0と区別する。各棒にポインターを合わせる、キーボードでフォーカスする、またはクリックして区間を選ぶと、その区間の詳細を確認できる。ラベルを省略した値も、選択した区間の詳細と全26区分の表で確認できる。

対象は[公式MRランキング](https://www.streetfighter.com/6/buckler/ja-jp/ranking/master)で、取得時に「今Act」「最大MR」「地域：すべて」「プラットフォーム：すべて」を選んだ掲載一覧。今Actは取得時の条件であり、保存後に現在のActへ自動で読み替えない。

- 0〜99、100〜199、…、2400〜2499の25区分と、2500以上の1区分を合わせた全26区分とする。区間の上限は含めず、1500〜1599は1500以上1600未満。
- 割合の分母は取得終了時のMR一覧掲載総数。「このMR以上」は区間の下限以上の累積件数を同じ分母で割る。計算では丸めず、表示時に丸める。
- 最大MRのキャラクターと最大LPのキャラクターが同じとは限らない。LP側のMASTER総数との対象の一致を仮定せず、LPのMASTERをMR割合で分割したり、件数の差を未プレイ人数と解釈したりしない。
- 公式の最大MR条件に基づく掲載件数を扱う。一部の観測ページに重複がないことから、未観測ページを含む全件の一意性は主張しない。別プラットフォームのアカウントを同じ人へ統合した実人数や、アクティブ人口でもない。
- MR未確定、今Act未プレイなどの未掲載理由は、この一覧だけから決めない。未掲載・未知・読み込み待ち・欠損を0MRや1500MRへ補完しない。

取得日が0件なら「未取得」、1件ならその取得日時を表示して選択不可、複数なら保存済みの取得日から選べる。未取得、取得失敗、読み込み失敗、確認済みの0件を区別する。総数0件のデータは件数0として保持し、割合・累積割合は算出不可とする。

## 境界から件数を求める方法

MR降順の一覧について、100〜2500の全25閾値を調べる。先頭・末尾とページ範囲を確認し、各閾値以上の掲載行が終わる位置を二分探索する。探索済みのページは次の探索の候補を絞るために使い、境界を確定する前に新しく読み直す。

件数には`(ページ番号 - 1) × ページサイズ + ページ内の行位置`を使う。同じMRでは表示順位が同じになるため、順位の差を件数にしない。各境界で最後の`MR >= 閾値`と最初の`MR < 閾値`を新しい読み取りで確認する。閾値が掲載範囲の外なら、先頭または末尾の新しい読み取りで0件・全件の境界を確認する。

たとえば1500以上の件数から1600以上の件数を引くと、1500以上1600未満の件数になる。全25境界の隣接差で全26区分を計算し、非負の整数、区分の不足・重複がないこと、件数合計と終了時総数の一致を検証する。

境界ごとの観測日時・観測総数と、取得期間内の総数の最小・最大、開始・終了時総数を保存する。異なる時刻の位置差から求めた概数なので、同一瞬間の人口分布ではない。総数の増減や件数合計の一致から、誤差上限や信頼区間は算出しない。

## ローカルで取得する

このPCの同じWindowsユーザーで、既存のローカル認証保存を済ませてから実行する。認証の保存・再利用については[認証の検証手順](auth-probe.md)を参照。

```powershell
node scripts/collect-mr-distribution.ts --collect
```

既存の`.local/buckler-auth-probe/private-session.dpapi`を同じWindowsユーザーで復号し、認証状態をメモリ内で新しい表示付きEdgeに渡す。MR取得コマンドからCAPCOM IDへのログイン、ロボット確認、認証の再保存は行わない。最初のページでログイン状態と完全な一覧を確認できなければ停止する。

通常のページ移動は開始を5秒以上空け、直列に行う。既定・最大とも600読み取り、実行全体の上限は30分。読み取り回数の上限は2〜600の範囲で指定できる。中止はCtrl+C。

```powershell
node scripts/collect-mr-distribution.ts --collect --max-requests 600
```

タイムアウト、通常の読み取り失敗、認証表示の確認待ち、HTTP 5xxのサーバーエラーは、1回の読み取りにつき同じページを1回まで読み直す。実際の再読も600回の上限に含める。アクセス拒否、待機後にも残るログイン要求、メンテナンス、固定条件や「今Act」の選択の不一致、境界やページ範囲の矛盾、時間・回数の上限、認証失効で停止し、無制限の再試行や全件列挙へ切り替えない。

先頭でログイン済みの完全な一覧を確認した後だけ、後続ページにログインボタンが表示されても、確認待ちの後に固定URL・今Act・条件・ページ範囲・全行を検証できれば読み取る。この場合の受理回数は`readableWithoutSignInReadCount`へ分けて記録し、ログイン状態を確認済みとは扱わない。ログイン要求の見出しや不正な一覧は受け入れない。

## 保存とアプリへの取り込み

全25境界を確認した集計だけを、`.local/mr-distribution/max-mr-estimate-取得開始日時.json`へ保存する。取得コマンドは既定ではローカル保存のみで、同じ名前のファイルへ上書きしない。部分取得は完成した分布として保存・表示しない。

取得成功後にアプリ用データへ取り込む場合は`--import`を付ける。

```powershell
node scripts/collect-mr-distribution.ts --collect --import
```

保存済みの集計を後から取り込む場合は、対象ファイル名を指定する。

```powershell
node scripts/import-mr-distribution-data.ts ".local/mr-distribution/取得済みファイル名.json"
node scripts/validate-mr-distribution-data.ts
```

取り込み先は`public/data/mr-distribution/`。入力をすべて検証してから一時フォルダーで次の一覧を組み立て、検証に成功した場合だけ置き換える。同じ取得期間の修正は入れ替え、他の取得日の履歴を保持する。入力が不正なら既存の正常データを保持する。

保存するのは出典、固定条件、取得期間、区間別件数、境界の観測値、検証結果だけ。個人名、プロフィールID、個別行、認証Cookieなどは集計ファイルや配信用JSONへ含めない。ページ内の重複確認に使う一時キーもメモリ内に限定する。未知のキー、全26区分・全25境界の不足、条件・日時・合計の不一致はパーサーで拒否する。

| 内容 | 実装 |
| --- | --- |
| データ型 | `src/types/mrDistribution.ts` |
| 条件と閾値、検証、ロード、表示行生成 | `src/lib/mrDistribution.ts` |
| 通常画面の読み取り | `scripts/lib/mr-distribution-dom.ts` |
| 境界探索と集計 | `scripts/lib/mr-distribution-collector.ts` |
| ローカル取得と認証再利用 | `scripts/collect-mr-distribution.ts` |
| 取り込みと配信フォルダー検証 | `scripts/import-mr-distribution-data.ts`、`scripts/validate-mr-distribution-data.ts` |
| 画面 | `src/components/MrDistributionPanel.tsx` |

## 検証コマンドと自動化の範囲

```powershell
npm run data:collect-mr-distribution -- --collect
npm run data:import-mr-distribution -- ".local/mr-distribution/取得済みファイル名.json"
npm run validate:mr-distribution
npm run test:mr-distribution
```

ローカルの単発取得に加え、GitHub Actionsの単発・週次取得と公開集計の自動反映に対応する。取得手順の実装、単発の実データ取得成功、週次の定期起動成功は別に記録する。

## クラウド取得とページへの自動反映

`.github/workflows/mr-distribution-weekly.yml`をmainから手動実行する。週次は金曜21:00 JSTの予定で、リポジトリ変数`MR_DISTRIBUTION_WEEKLY_ENABLED`が`true`のときだけ収集する。単発検証が完了するまでは同変数を未設定または`false`にしておく。GitHub Actions側の都合で実際の起動時刻は遅れることがある。

- 認証は既存の`BUCKLER_WEEKLY_SESSION`を再利用し、新しい認証情報は保存しない。受け取った環境変数を削除してから検証し、ブラウザーへメモリ内で渡す。LP週次・Legend日次の取得条件やSecretは変更しない。
- `collect-mr-distribution-weekly.ts`は既存のMR取得処理を使う。直列・開始間隔5秒以上・最大600読取・30分を維持する。ログイン要求、CAPTCHA、条件の不一致、上限超過では停止し、部分的な境界値を完成分布として保存しない。
- 取得ジョブは書込権限を持たず、検証済み集計と固定項目の実行記録だけをartifactへ渡す。認証情報・個別行・HTML・スクリーンショットは出力しない。
- 保存ジョブが全26区分・25境界・出典・取得期間・合計と実行記録を再検証し、`codex/mr-distribution-history`の`public/`と`runs/`へ保存する。初回は既存の同梱データを引き継ぐ。取得失敗時には過去の正常な集計を保持し、失敗した実行の記録と取得状態を追加する。
- ページは同ブランチの`public/index.json`と集計JSONを読み込む。LP・Legendと共通の`publishedDataFeed`と`usePublishedData`により、表示時・表示中の5分ごと・タブへ戻ったときに再確認する。最新日を表示中なら新しい取得分へ移り、過去の日付やグラフの設定は維持する。
- 初回にクラウド履歴を読めなければ同梱データを表示し、更新中に通信が失敗した場合は表示中の正常値を保つ。一覧と本体は同じ配信元で検証し、不完全な履歴や取得日が後退する更新へは切り替えない。

手動実行はGitHub Actionsの「Collect weekly MR distribution」から行う。収集から履歴保存まで成功したことと、ページの取得日・総数が保存した集計と一致することを確認する。週次を止める場合は`MR_DISTRIBUTION_WEEKLY_ENABLED`を`false`にする。共有の認証Secretを削除するとLP・Legendにも影響するため、MRだけを停止する操作として削除しない。

| 内容 | 実装 |
| --- | --- |
| クラウド取得・実行記録 | `scripts/collect-mr-distribution-weekly.ts` |
| 集計履歴の保存 | `scripts/publish-mr-distribution-weekly.ts` |
| ページの自動読込 | `src/lib/mrDistributionFeed.ts`、`src/components/MrDistributionPanel.tsx` |

## 初回取得の確認記録

同日、人間確認を完了した同じブラウザーで23:06:58〜23:19:19 JSTに新しい取得を行い、全25境界の観測と再読み取りに成功した。106回の正常なページ読取を検証し、26区間・合計314,404件の概数をアプリへ取り込んだ。観測した掲載総数は314,389〜314,404件。以前の停止前の境界値は完成値として流用せず、探索位置の候補にだけ使った。

取得・集計・取り込みの合成データテスト、型検査、ビルドは成功した。仮データ専用のローカル画面で522pxと1280pxの26区分表示、件数と割合の切り替え、総数0件時の算出不可も確認した。今回の取得成功はログイン済みブラウザーでの実証であり、保存済み認証を再利用するCLIによる全体取得の成功や、MRのクラウド・週次実行の成功を示すものではない。
