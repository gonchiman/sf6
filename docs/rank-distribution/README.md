# ランク分布の取得・公開仕様

## 集計単位

対象は、BucklerのLPランキングを「リーグ：総合」「キャラクター：最大LP」「地域・プラットフォーム・ユーザー：すべて」で表示した一覧の登録ファイターアカウント。ランク別件数を合算し、その総件数を割合の分母にする。

- 同じアカウントが使う複数キャラクターの件数と、アカウント件数を混ぜない。
- SteamとPS5等で別のファイターアカウントを持つ同じ人を、公開ランキングから統合した実人数ではない。CAPCOM IDの連携とランキングのユーザーコードを区別する。
- 直近のランクマッチ参加人数ではない。最終プレイ日時だけから、ランクマッチの活動期間を確定しない。
- 最大LPのキャラクターに基づく掲載ランクを使う。過去最高到達ランク、現在主に使うキャラクターのランク、MRの分布とは別の指標。
- ID 1〜35はROOKIE〜DIAMONDの各★1〜5、36はMASTER。Legend等のMR区分を別に加算しない。

出典は[公式LPランキング](https://www.streetfighter.com/6/buckler/ja-jp/ranking/league)。ファイターアカウントは[公式マニュアル](https://game.capcom.com/manual/SF6/en/ps5/page/1/1)の定義を参照する。[CAPCOM IDのFAQ](https://cid.capcom.com/ja/support/)は、異なる種類のプラットフォームアカウントを同じCAPCOM IDへ連携できると説明している。

## 現在の確認範囲

2026-10-13の通常の公式UIでは、最大LPと個別リーグの指定が互いにリセットされ、同時条件を直接指定しても正常な集計一覧を確認できなかった。したがって「最大LP＋ランク別フィルターの総件数を36回読む」方式は採用しない。総合キャラクター条件のMASTER件数はキャラクターの掲載件数であり、最大LPのアカウント件数には流用しない。

最大LP・リーグ総合でLastを操作すると、URLの`page=152759`へ遷移したが、表示はメンテナンスとなった。URLの変化だけでは深いページの正常な到達・数値の読み込みを確認したことにしない。現行の取得アダプターと最終ページの内容は未検証で、初期の配信一覧は空。未取得・取得失敗を全ランク0件のデータセットとして保存しない。

[非公式の当事者による観測資料](https://github.com/Matars/buckler-api-docs/blob/main/docs/endpoints.md#rankings)に、ランキングのページサイズ、条件メタデータ、総件数等が記載されている。ただしCapcomの公式API仕様ではなく、現行セッションの動作確認の代わりにはしない。認証情報、内部状態、非公開データを公開JSONに含めない。

## 境界探索ヘルパー

[`scripts/lib/rank-distribution-boundaries.ts`](../../scripts/lib/rank-distribution-boundaries.ts)は、読み取り関数`fetchPage(page, url)`を注入する純粋な集計処理。ネットワーク取得、認証、DOM操作、全件取得への切り替えは実装していない。アダプターは正常な公式表示と、許可された読み取り経路を確認してから接続する。

固定条件URLは以下。ページ番号だけを差し替え、他の条件を追加・変更しない。

```text
https://www.streetfighter.com/6/buckler/ja-jp/ranking/league?character_filter=2&character_id=luke&platform=1&user_status=1&home_filter=1&home_category_id=0&home_id=0&league_rank=0
```

`character_id=luke`は確認済みの最大LP条件URLに残る値。特定キャラクターを対象にした集計へ変更しない。フィルターの値・名前が変わった場合は、現行UIで確認し、ヘルパーを更新してから使う。

アダプターが返す`RankBoundaryPage`：

| 項目 | 入力仕様 |
| --- | --- |
| `sourceUrl` | 実際に表示・確認した公式ページURL。要求した`page`を含み、固定条件と一致すること |
| `page` | 読み込まれた一覧のページ番号。要求番号をそのまま代入して到達の証拠にしない |
| `pageSize` | 現行の通常ページ件数。20件という過去の観測を未確認の既定値にしない |
| `totalCount`, `totalPages` | そのページで確認した総件数・総ページ数 |
| `entries` | 表示順の`{ leaguePoint, rankId, accountKey? }[]`。LPは整数、ランクは1〜36 |
| `accountKey` | 重複検査用の任意の安定した私的キー。ヘルパー出力・公開データへは含めない |

LPとランクIDの境界`ranks: { rankId, minimumLp }[]`は36区分すべてを呼び出し側から渡す。古いLP表の既定値は持たず、現行の表示との対応を確認する。未ランク、読み込みプレースホルダー、不明なリーグ画像をROOKIEや0件に変換しない。

手順は、先頭・末尾を確認し、各ランクの最低LP未満になる最初の行位置を二分探索する。隣接する境界位置の差から各区分の件数を計算する。位置は`(page - 1) × pageSize + 行の位置`を使い、同LPで同順位になり得る表示順位の差を人数として使わない。境界の前後と先頭・末尾を別の読み取りで再確認する。

ヘルパーは以下を拒否する。

- 固定条件からの変更、要求ページへの未到達、ページ数・件数・末尾件数の不一致。
- LP順の逆転、LPとランクIDの不一致、観測したキーの重複・位置変化。
- 取得中の総件数変更、再確認時のページ内容変更、取得失敗・メンテナンス。
- 取得回数上限または中止。キャッシュを再確認の別観測として数えない。

ヘルパー成功時の`observedChecks`は確認した範囲の検査結果であり、配信可能な`verified`データセットではない。特に`max-lp-account-unit-confirmed`と`unranked-tail-confirmed`を自動付与しない。一部ページで重複がなかったことだけから全件の一意性を証明しない。

## 公開前の検証

配信データは[`RankDistributionDataset`](../../src/types/rankDistribution.ts)に従い、次のすべての確認を要求する。各確認の根拠を`validation.notes`へ記録する。確認コードを書いただけで未検証の取得を検証済みにしない。

| 確認コード | 必要な確認 |
| --- | --- |
| `conditions-confirmed` | 総合・最大LP・全地域・全プラットフォーム・全ユーザーで読み込まれた一覧 |
| `pagination-confirmed` | ページ番号・通常ページ件数・総ページ数・総件数の整合と深いページへの正常到達 |
| `final-page-confirmed` | 最終ページが表示でき、末尾の件数が総件数と一致 |
| `ordering-confirmed` | LP降順とページ間の順序。同LPの行を取り落とさない |
| `rank-mapping-confirmed` | 現行のLPと36ランクの対応 |
| `max-lp-account-unit-confirmed` | アカウント単位に最高LPのキャラクターが掲載される集計定義の根拠 |
| `total-count-stable` | 取得期間内のすべての観測で総件数・ページ構成が一致 |
| `boundaries-rechecked` | 境界の前後を新しい読み取りで再確認して一致 |
| `unranked-tail-confirmed` | 未ランク・不明区分の扱いを確認し、欠損の補完を行っていない |

LPランキングには取得月の選択がないため、データを月次統計として遡って復元しない。`captureStartedAt`と`captureEndedAt`を持つ取得期間の観測として保存する。開始・終了で総件数が一致しても、その間のランク移動を排除した原子的なスナップショットとは主張しない。

一部の境界だけ確認できても、36区分の完全集計として公開しない。境界の中間位置を正確な件数にしたり、根拠のない信頼区間を付けたりしない。失敗時は前回正常値を保持し、一覧の`availability`へ取得状態・確認日時・理由を残す。全件取得へ自動で切り替えない。

## JSONの取り込み・検証

[`scripts/import-rank-distribution-data.ts`](../../scripts/import-rank-distribution-data.ts)は、単一の検証済みデータセット、同形式JSONだけを置いたフォルダー、または`{ schemaVersion: 1, datasets: [...] }`というバンドルを取り込む。入力は必須で、確認済みの取得データがない状態を人工の0件集計で埋めない。

```powershell
npm run data:import-rank-distribution -- .cache/rank-distribution/verified-capture.json
node scripts/validate-rank-distribution-data.ts
```

入力バッチ全体を検証し、排他ロックを取得して、既存一覧を検証、作業先へステージング、ステージ全体を再検証した後に入れ替える。失敗時は既存データを復旧する。同じ取得開始・終了の記録だけを置き換え、他の取得記録は保持する。

36区分の不足、重複、件数合計の不一致、未検証・部分取得、日時の矛盾、個人情報等の未知キー、パストラバーサル、Windows予約名、リンク、未登録ファイルは拒否する。取り込みが成功すると過去の取得失敗表示を解除する。画面へ配信するJSONには集計値・取得条件・出典・期間・検証結果だけを含める。

既存の勝率スナップショット、使用率のimport/validation、勝率のステージング・復旧方式を参照し、ランク分布の厳密な条件と個人情報の検査を追加した。境界処理・欠損・同LP・更新中の変化・条件リセットと、無効バッチで既存ファイルが変わらないことを人工データのテストで確認する。人工テスト値は実データとして配信しない。
