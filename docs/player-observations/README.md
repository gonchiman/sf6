# 新規参入観測

`#new-account-observation` は、同じ取得条件で初めて観測したCFNアカウントを確認するページです。
実際の初プレイ日時・参入日時・新規プレイヤーの実人数は確定できません。
別アカウント、初めてランクマッチを始めた既存プレイヤー、以前の走査で未観測だったアカウントを含み得ます。

## 画面

「条件選択」「新規観測アカウント数」「選択した観測回」の3パネルを縦に配置します。グラフはありません。
期間はJSTの日付で観測区間との重なりを判定し、最新の観測回を初期選択します。
日を跨いだ走査を1日分の新規参入数として扱わず、開始・終了日時を表示します。

対象はBucklerのLPランキングの総合・最大LP・全地域・全プラットフォーム・全ユーザーです。
Rookieなどのランク別・キャラクター総合の取得記録は混ぜません。
「観測ID数」は各観測回で取得した重複のないID数です。観測回を跨いで同じIDが現れるため、単純合算はしません。

状態は次のように表示します。

| 取得状態 | 新規観測アカウント数 |
| --- | --- |
| 基準走査 | 算出前。取得ID数を新規数にしない |
| 基準作成後の走査完了 | その走査区間で初めて確認したID数。0件も表示する |
| 基準作成後の部分取得・取得中 | 主件数は算出不可。確認できた範囲の下限を暫定表示する |
| 取得失敗・欠測 | 算出不可。0件で補完しない |
| 公開JSONの読込失敗 | 再読み込み。収集の失敗とは区別する |

全対象ページを訪問しても、走査中の順位・LP・表示総件数の変動により単一時点の完全な名簿にはなりません。
基準作成後の部分取得で見つけたIDは、その観測回の初観測として残します。
後の再取得で初観測日時を移したり、復帰したIDを再計上したりしません。

## 取得記録と履歴

この実装の収集器は、通常画面から保存した検証済みページ記録を読み込む **inboxアダプター** です。
Bucklerへの直接JSON取得、認証情報の自動更新、バックグラウンド全件取得、毎日の自動更新は設定していません。
全件取得の所要時間、認証継続、アクセス制限、途中の順位変動の影響は別途実測が必要です。

通常のランキング画面で対象条件を適用し、ページ移動が完了した後、DevToolsで
[export-player-observation-page.js](../../scripts/export-player-observation-page.js)を実行すると、そのページのJSONを保存できます。
ランキング本体の数値CFN ID・LP・順位・表示範囲・時刻だけを取得します。
表示名、自分の順位カード、Cookie、認証ヘッダー、隠し状態は取得しません。
同点順位とページ内の行位置は別として検証します。

同じ観測回のページ記録JSONを `.local/player-observations/snapshots/<run-id>/` に集めます。
同じページの記録を複数入れず、再取得を別の観測回にするか、採用する記録を1つ選びます。
実行時刻より未来の取得記録は、履歴を作成・変更する前に拒否します。

```sh
npm run data:prepare-player-observations -- .local/player-observations/snapshots/<run-id> <run-id> probe
npm run data:collect-player-observations -- .local/player-observations/inbox/<run-id>.json
npm run data:publish-player-observations
npm run validate:player-observations
```

`run-id` は小文字英数字・ハイフンで96文字以内です。`probe` は部分範囲の検証です。
`population` を指定しただけでは基準完成・走査完了になりません。実際のページ集合と失敗状況から認定します。
取得入力はすべて検証してから履歴へ取り込みます。同じページ記録の再実行は冪等で、異なる内容を黙って上書きしません。
ページごとの保存により中断後に同じ入力を再実行できます。

予定した観測回を取得できなかった場合は、取得記録を捏造せず欠測を明示します。
予定日時は過去または現在のISO UTC日時です。未来の予定を欠測登録できません。
同じID・予定日時での再実行は二重登録しません。

```sh
npm run data:collect-player-observations -- --missing <run-id> <scheduled-at-utc>
npm run data:publish-player-observations
```

非公開のSQLite履歴は `.local/player-observations/history.sqlite` に保存します。
CFN IDは文字列のまま扱い、系列とIDの組で重複を排除します。
初観測時刻・所属観測回・基準作成段階を保持し、観測から消えたIDも残します。
SQLiteはNode.js 24の `node:sqlite` を使います。外部パッケージの追加はありません。

## 公開

公開先は `public/data/player-observations/index.json` です。
集計件数、取得状態、取得範囲、走査区間、出典、生成日時、形式・定義・系列を保存します。
CFN ID一覧、SQLite、取得入力、認証情報は公開先に含めません。
入力検証・公開データの検証後に置き換え、失敗した更新で以前の公開ファイルを壊さない処理を使います。

`schemaVersion` はJSON形式、`definitionVersion` と `seriesId` は観測定義を識別します。
v1は上記条件だけを受け付け、異なる条件や定義の記録を連結しません。
新しい観測定義を導入するときは、履歴・基準・表示を対応させて新たな系列を作成します。

初期の公開記録は2026年10月13日の通常画面による検証です。
前回の上位3ページ60 IDと、追加確認の先頭・最終ページ28 IDの2回を基準準備として表示します。
両記録は部分取得で、新規数は未算出です。低ランク側の別条件の記録は含めません。

画面は既存の `StatisticsPanel`、`DataLoadState`、共通テーブル、行選択、日時表示を再利用しています。
