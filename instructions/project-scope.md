# プロジェクトの目的と実装方針

このプロジェクトの作業開始時に読む。

## 目的と優先順位

- Street Fighter 6の勝率・使用率を分析するアプリを作る。初期の優先対象はキャラクターの勝率・使用率と、その条件別の比較とする。
- 大会成績や個別プレイヤーの分析は、勝率・使用率分析より後の拡張として扱う。依頼されていない機能まで初期実装に含めない。
- データの取得元、提供される項目、利用条件を確認してから機能を具体化する。Bucklerやstart.ggを利用候補として扱い、未確認のデータ項目や取得方法を利用可能と断定しない。

## 実装の基本方針

- `arknights_2` の後継として、同じ実装方針を基本とする。React・TypeScript・Viteを使い、GitHub Pagesで配信できる静的なWebアプリを想定する。
- UI、データの型、取得・正規化・集計の処理を分離する。配置は `src/components/`、`src/types/`、`src/lib/` などの役割別の構成を基本とする。
- 大量データや認証が必要な取得は、事前の取得・集計処理で配信用JSONにする。公開済みデータの絞り込みや表示に必要な計算はブラウザー側で行う。
- データの出典、対象期間、取得日時・生成日時、形式のバージョンを管理し、分析結果の根拠を確認できるようにする。
- APIトークンなどの秘密情報を、ブラウザーへ配信するコード・JSON・公開リポジトリに含めない。
- GitHub Actionsでは変更に必要なテスト・ビルド・配信を分けて扱う。データ更新の頻度や自動取得の仕組みは、取得元と更新方針が決まってから定める。

## 初期ルールと実装の区別

- 指示・仕様を保存しただけで、対応する機能や共通部品が実装済みであると扱わない。
- 実装、データ取得、自動更新、公開は、その作業の依頼範囲に応じて行う。
